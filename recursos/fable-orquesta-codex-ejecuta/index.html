Fable orquesta, Codex ejecuta

Cómo hacer que Fable piense y Codex construya sin quemar tus límites de Claude.

10 min de lecturaClaude a fondoFableCodex
Ideal para
  • Quien usa Fable en sesiones de Code
  • Proyectos que necesitan un plan antes de construir
  • Equipos que quieren delegar sin perder revisión
Qué obtienes
  • Flujo de roles entre Fable y Codex
  • Prompts para planificación y proyectos grandes
  • Delegación, revisión y debugging
  • Comandos esenciales del plugin

Si ya conectaste Codex con Claude Code, ahora viene la parte importante: aprender a repartir el trabajo.

En lugar de pedirle a Fable que analice, diseñe, escriba, haga refactors y arregle errores, conviértelo en el orquestador. Codex se encarga de la construcción pesada.

1. La idea

Fable → El cerebro

  • Entender el proyecto y explorar el código.
  • Hacer preguntas, pensar la solución y crear el plan.
  • Dividir el trabajo y revisar lo que construyó Codex.

Codex → El constructor

  • Escribir código y modificar archivos.
  • Construir funcionalidades y hacer refactors.
  • Resolver tareas pesadas siguiendo el plan.

2. ¿Por qué hacer esto?

No necesitas que el mismo modelo analice el proyecto, diseñe la arquitectura, escriba 15 archivos, cree componentes, refactorice, arregle errores y haga tests.

flujo
FABLE
Pensar · Planear · Decidir · Revisar
   ↓
CODEX
Construir · Modificar · Refactorizar · Ejecutar

Codex utiliza la cuenta de ChatGPT para su consumo en la construcción delegada. Los límites y condiciones concretos dependen de tu cuenta y pueden cambiar.

3. Antes de empezar

  • Claude Desktop o Claude Code.
  • Una sesión de Code.
  • Fable seleccionado como modelo.
  • El plugin oficial de Codex instalado y configurado.
  • Una cuenta de ChatGPT para ejecutar Codex.

Si todavía no tienes Codex instalado, primero completa la guía Cómo trabaja Claude Code + Codex: Plugin Oficial.

4. El primer paso: pon a Fable en modo Plan

“Analiza esto y hazme el plan.”

Fable debería explorar el proyecto, identificar archivos y dependencias, definir la arquitectura, dividir el trabajo y decidir cómo comprobar que funciona. Todavía no debe construir.

5. Prompt principal: Fable planea, Codex construye

prompt
Vamos a repartir el trabajo.

Tú, Fable, eres el cerebro: planea, no construyas.

1. Explora este proyecto y entiende qué quiero lograr.
2. Ármame un plan claro en modo Plan:
   - qué archivos se tocan
   - en qué orden
   - qué decisiones hay que tomar
   - qué hay que probar al final
3. Hazme las preguntas que falten antes de escribir código.
4. Cuando yo apruebe el plan, NO lo construyas tú.
   Pásale la construcción a Codex utilizando: /codex:rescue
5. Cuando Codex termine, tú revisas lo que hizo utilizando: /codex:review
6. Después dime en una línea si quedó bien o qué falta corregir.

Regla: Tú piensas y revisas. Codex construye.
Empieza por el plan. No escribas código todavía.

6. Qué ocurre después

Fable debería entregarte un plan con los archivos, cambios, validaciones, tests y build. Tú revisas el plan; si está bien, lo apruebas. Ahí comienza el trabajo de Codex.

7. Delegar la construcción a Codex

El comando principal es /codex:rescue. No digas solo “Hazlo”: dale el plan y las restricciones.

prompt
/codex:rescue

Implementa el plan aprobado por Fable.

OBJETIVO: Agregar autenticación con Google.
PLAN:
1. Crear el endpoint de autenticación.
2. Integrarlo con el sistema actual.
3. Actualizar el estado del usuario.
4. Manejar errores.
5. Agregar las pruebas correspondientes.

REGLAS:
- No cambies la arquitectura existente.
- No agregues dependencias nuevas sin justificarlo.
- No modifiques funcionalidades no relacionadas.
- Mantén las interfaces existentes.
- Ejecuta las pruebas al terminar.

Al finalizar entrega resumen, archivos modificados, pruebas ejecutadas, problemas encontrados y decisiones que Fable deba revisar.

8. Fable vuelve a entrar

Cuando Codex termina no significa automáticamente que esté bien. Usa /codex:review para revisar el código sin modificarlo y deja que Fable evalúe el resultado general.

9. Para proyectos grandes: divide el proyecto en tareas

No le des a Codex “construye toda mi aplicación”. Divide, por ejemplo, autenticación, dashboard, pagos, notificaciones, panel administrativo y tests.

Cada tarea necesita objetivo, archivos, restricciones, criterio de terminado y pruebas. Así Fable revisa cada parte antes de pasar a la siguiente.

10. Prompt para proyectos grandes

prompt
Quiero trabajar este proyecto con una división estricta de roles.

TU ROL — FABLE
Tú eres el cerebro: piensas, exploras, planeas, tomas decisiones de arquitectura, divides el trabajo y revisas los resultados.
NO escribas código de producción directamente. Trabaja en modo Plan hasta que yo apruebe.

Divide el proyecto en tareas pequeñas y ordenadas. Cada tarea debe tener objetivo, archivos involucrados, cambios necesarios, dependencias, criterio de "listo" y pruebas necesarias.

ROL DE CODEX
Cada tarea aprobada se la pasas a Codex utilizando /codex:rescue, con suficiente contexto.

CICLO POR TAREA
1. Fable planea.
2. Fable muestra el plan.
3. Yo apruebo.
4. Codex construye.
5. Fable revisa.
6. Si está bien, seguimos con la siguiente tarea.
7. Si hay problemas, corregimos antes de continuar.

REGLA PRINCIPAL: Fable piensa y revisa. Codex construye.
Empieza explorando el proyecto y proponiendo el plan completo. No escribas código todavía.

11. Los comandos que más vas a utilizar

ComandoUso
/codex:rescueDelegar construcción, debugging, refactors e investigación.
/codex:reviewRevisar código antes de aceptar cambios importantes.
/codex:adversarial-reviewBuscar por qué la solución podría estar mal.
/codex:transferContinuar en una sesión persistente de Codex.
/codex:statusVer trabajos activos.
/codex:resultVer el resultado de un trabajo terminado.
/codex:cancelCancelar un trabajo.

12. Cuando Fable se atasque

Después de dos intentos fallidos, no sigas en el intento 3, 4 o 5: delega con /codex:rescue.

prompt
Tenemos este error: [ERROR]

Ya intentamos:
1. [INTENTO 1]
2. [INTENTO 2]

Investiga la causa raíz. Antes de modificar código revisa implementación, configuración y logs. Después implementa el arreglo, ejecuta las pruebas y explica qué causaba el problema. No cambies partes no relacionadas.

13. Utiliza Codex como abogado del diablo

Antes de hacer commit o pasar a producción, usa /codex:adversarial-review.

prompt
Haz una revisión adversarial de los cambios actuales.

Busca bugs, casos límite, problemas de arquitectura, código innecesariamente complejo, dependencias innecesarias, problemas de seguridad, regresiones y problemas de producción.

No modifiques ningún archivo. Devuelve los problemas ordenados por severidad e indica archivo, línea, problema, por qué importa y cómo solucionarlo.

14. Cómo trabajar en segundo plano

Para tareas largas, delega y continúa trabajando. Consulta /codex:status y, cuando termine, /codex:result.

prompt
/codex:rescue

Refactoriza este módulo siguiendo el plan aprobado.

Objetivos:
1. Eliminar duplicación.
2. Separar responsabilidades.
3. Mantener exactamente el comportamiento actual.
4. No agregar funcionalidades nuevas.
5. Ejecutar las pruebas existentes.

Si una decisión requiere arquitectura, no la improvises: detente y repórtala. Al finalizar entrega un resumen archivo por archivo.
La regla de oro: Fable piensa y revisa. Codex construye.
